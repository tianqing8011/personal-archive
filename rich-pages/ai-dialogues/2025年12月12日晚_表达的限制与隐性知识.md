## 三、解剖转译层

### 1. 为什么 AI 能做得好、代码却做不到？（LLM vs 传统程序）

| 维度 | LLM（对话式 AI） | 传统代码/脚本 |
|---|---|---|
| **处理方式** | 整体理解，同时考虑所有上下文与关联 | 线性执行，按预设规则逐步跑 |
| **匹配能力** | 模糊匹配，容忍不完全符合模式的情况 | 需要明确规则，边缘情况难以处理 |
| **知识来源** | 海量文本学习出的"经验" | 只有明确编写的逻辑 |
| **规则记忆** | 可能遗忘、需提醒 | 写入即永生 |
| **表达极限** | 处理能力强，但难以解释"为什么" | 规则必须显式写出，无隐性理解 |

**核心矛盾：** AI 的强项恰恰是它"说不清"的部分——模糊、整体、直觉式的理解；而代码的强项（确定性、可复现）需要的是"说得清"的规则。用户要做的，是把前者翻译成后者，而翻译必然有损耗。

### 2. 两个认知概念（AI 引入的框架）

**知识诅咒（Curse of Knowledge）：** 知道的越多，越难理解别人"不知道"是什么状态。专家无法向新手解释全部隐含知识，不是不愿，而是那些知识对他已是呼吸般自然。

**隐性知识 vs 显性知识：**
- 隐性知识（tacit）：知道怎么做，但难以言说——骑自行车、识别面孔、AI 的文本理解
- 显性知识（explicit）：可以写下来、教给别人——操作手册、代码规则、菜谱

**AI 的立场：** 文本处理能力部分是隐性知识，难以形式化，所以代码无法完全复刻。
**用户的立场（更进一层）：** 隐性知识**不是不能表达**，而是还没找到对的表达方式。历史上一再发生这种突破——机器码→汇编→高级语言→面向对象→函数式，每次都是"新的表达方式"解锁了"原来表达不了的东西"。

### 3. Cursor 能否不用 API 直接用大模型？（三种方案）

| 方法 | 操作 | 适合场景 |
|---|---|---|
| **Cursor 聊天功能** | 订单文本存成 txt → 粘贴进聊天面板 → 要求整理成表格 → 复制结果 | 零门槛，最直接 |
| **辅助脚本** | 写个 Python 小脚本：选文件→读内容→拼好指令→一键复制到剪贴板 | 每次少粘一段，仍走聊天 |
| **命令面板** | 打开订单文件 → Ctrl+Shift+P → 输入"整理成表格"类命令 | 文件已在编辑器内 |

**关键结论：** Cursor 内置激活的模型（Opus 4.5、GPT-5.1 Codex Max 等）本身就能处理文本，**不需要 POE API**。POE 的 API key 属于另一套体系，在 Cursor 里不通用（前半场已确认）。

### 4. 如果真要走 API 自动化（保留大模型能力 + 程序化）

思路：脚本只做"拼指令 + 发请求 + 收结果"，把**理解部分**交给大模型，而不是写死规则。
```python
import requests
# 伪代码骨架
# 1. 读取原始订单文本
# 2. 拼接系统指令（含四表格式、姓名分类、电话规则、县级地址规则）
# 3. POST 到模型 API（含 POE 或 Anthropic）
# 4. 解析返回的表格文本 → 写入 Excel
```
**成本对比：** API 有调用费用，但比"反复纠正对话/反复改代码"的时间成本可能更划算。这是 AI 时代的新性价比逻辑。

### 5. 从"教它怎么做"到"告诉它做什么"

> "有些任务，我们不再需要教计算机'如何'做，而是直接告诉它'做什么'，然后让模型自己处理细节。"

这是 AI 编程范式的转向：传统编程是"教怎么做"（写死每一步），LLM 时代是"告诉做什么"（描述意图，模型负责细节）。**而"告诉做什么"依赖的正是表达能力——用户悟到的那个核心命题。**

### 6. 人机交互中的"意图传递"

AI 的补充视角：
- 人类与 AI 的挑战，不在于详细说明"怎么做"，而在于清晰表达"我想要什么"
- 使用 AI 是**双向学习**：人在学如何表达意图，AI 在交互中学用户期望
- 这种共同适应会逐渐缩小表达鸿沟——用户每次"指出错误"其实都是在训练一个更好的接口

### 2. 双轨工作流（用户确定的计划）

```
轨道 A（对话式）：粘贴原始文本 → 本 AI 直接整理 → 返回表格
轨道 B（代码式）：在 Cursor 里和 AI 反复迭代订单脚本 → 跑出四表 Excel
每天两边都跑一遍 → 对比结果 → 把对话中出现的"新规则"补进代码
```

### 3. "表达"的练习模板（把规则写清楚的范式）

写指令时遵循这个结构，表达就不会漏：
```
1. 输入是什么：原始订单文本（微信群格式）
2. 输出是什么：四个表格，每个表格几列、列名是什么
3. 转换规则：电话[代码]→电话-代码；姓名分类；县级地址加提示语
4. 例外处理：同一条消息含多订单怎么办、缺信息的订单怎么办
```

### 4. 待补充的规则（今天仍没完全解决的）
